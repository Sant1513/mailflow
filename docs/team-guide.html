MailFlow, from first sign-in to first reply

Email students from your own Gmail: import a batch, write one template, preview it per student, get it approved, send, and see every reply threaded back to the student it came from. Nothing goes out without a dry run and a human decision.

Sign in with your Google account Sends from your own Gmail address Approval required before any campaign sends

01Day-one setup

Do these in order. The whole thing takes about five minutes.

  1. Sign in at mailflow-six-sooty.vercel.app with Continue with Google.
  2. Connect Gmail: Settings → Gmail → Connect. Approve the two permissions (send, read). MailFlow sends from your own address and never as anyone else. If Google says "Gmail API has not been used", tell the super admin — it is enabled once for the project.
  3. Check your role in Settings → Profile. If it is wrong, a super admin changes it (see §2).
  4. Pick a theme at the bottom of the sidebar: System, Light or Dark. Remembered per browser.
  5. Send yourself a test: Templates → any template → Send test email. Confirm it lands before your first campaign.

03The core workflow

3.1 Import data Data

  • + Dataset, or Import → paste from Google Sheets or Excel, or upload CSV / XLSX.
  • The preview detects headers and types and flags duplicate emails: Keep first, Keep latest, or Import all.
  • Set the email column's type to EMAIL (the small type selector under the column header). That is what makes a dataset sendable and links each row to a Contact.
Importing never sends anything. Neither do previews, dry runs or AI suggestions.

3.2 Work the grid

  • Double-click a cell to edit. Click a header to sort; again for descending; again to clear. Drag a header edge to resize. Freeze first column keeps names in view.
  • Filter builds conditions in the same language as automations (equals, contains, is empty…). System fields such as Email Status and Reply Received are available.
  • Group by any column shows counts per value. Search matches every column.
  • Save view keeps a filter, sort and grouping under a name for everyone using the dataset.
  • Bulk edit: tick rows → Set column… to value → Apply. Each change is recorded per record; automations that trigger on updates will evaluate, and the confirmation says so.
  • Columns panel: show, hide, rename, reorder, delete. Rows: ⧉ duplicates, ✕ deletes.

3.3 Write a template Templates

  • Subject and body use variables from the dataset: {{Name}}, {{Deadline}}. Insert them from + Insert variable so the spelling matches the column.
  • Preview as a real student shows resolved values; unresolved variables are listed in yellow. Check layout with the width slider or the Desktop / Mobile presets.
  • AI assistant (left panel): describe the email → Generate → Insert. Improve, Shorten, More professional, Fix grammar and Translate rewrite the current body. Subject ideas and Check personalisation are advisory.
  • Format pretty-prints the HTML without changing how it renders. Run health check before saving: it catches missing variables, a non-EMAIL recipient column, broken links and a missing mailbox.
  • Save new version: every save is a new immutable version. Campaigns pin the version they were created with, so editing a template later never changes an email that already went out.

3.4 Build a campaign Campaigns

  1. + Campaign: name, dataset, template. The template version is pinned at this moment.
  2. Sender settings: From name, Reply-To, CC / BCC. CC and BCC go on every email in the campaign, so they are for supervisors and archives, not per student. The From address is always your connected Gmail.
  3. Run simulation: exactly who would receive, who is skipped and why (invalid email, duplicate, automation stop condition). No email is sent.
  4. Review: the exact headers and the rendered email per recipient. Read at least three.
  5. Submit for approval. Approvers get an email from your Gmail with you in CC. You cannot approve your own campaign.
  6. After approval, Send now. Sending creates a batch.

3.5 Approve Admins

  • Approvals in the sidebar; the badge is the pending count. Tabs Pending, Approved, Rejected, All; search by campaign, requester or workspace.
  • Approve takes optional internal remarks. Reject requires a reason, which the requester sees.
  • The decision is emailed back in the same thread as the request. If nobody has Gmail connected, the decision still happens and the row says why the email was skipped.
  • The campaign page shows the same buttons plus the full approval trail.

3.6 Watch the send Batches

  • Every batch with live progress: sent, failed, skipped, and how many are still queued. It refreshes itself while anything is running.
  • Process queue pushes queued emails through now. Pause, Resume and Cancel are immediate. Retry failed re-queues only the failures.
  • Emails leave at 20 per minute per mailbox by default, so a 300-student batch takes about 15 minutes. Gmail also enforces its own daily limit on your account.

3.7 Replies Inbox

  • Replies are pulled from your Gmail into the Inbox, only for threads MailFlow started. Push delivery is not on yet: click Sync now to fetch the latest.
  • Bounces, out-of-office and auto-replies are classified automatically and never count as "the student replied".
  • In a conversation: reply in the same thread or start a new one, add an internal note, tag, assign, set a follow-up, change status. AI suggest reply drafts text you can Insert and edit; Summarise gives a summary and a suggested next action that you choose whether to apply.
  • Every conversation links to the Contact and the record it came from.

3.8 Contacts and History

  • Contacts: a student's timeline across datasets — every email sent, every reply, notes and status changes.
  • History: the immutable log. Sent lists every email with its outcome, reason and retries and a "Why?" explanation. Received lists every inbound message with its classification. Search and filter by status.

3.9 Dashboard

Live numbers for your workspace: emails sent, pending, failed, replies, unread, open conversations, follow-ups due; a 30-day send chart; the approvals chart; recent batches, conversations and activity; quick actions.

04Automations

  • An automation sends a template when a record matches conditions, for example Trigger = 1 AND Status is empty, on record created or updated, with a frequency policy and cooldown so nobody is emailed twice by mistake.
  • Stop conditions such as Reply Received = true are checked first and always win.
  • Enabling shows how many records it would affect right now and asks you to acknowledge that number. Run Preview first.
  • Every run is listed with its result and a "Why?" explanation.

05Super Admin tools

  • Users: roles, enable and disable. Role changes are audited.
  • Workspaces: every user's workspace with counts. View Workspace opens it read-only under a red VIEWING WORKSPACE AS banner; Exit View leaves. Entry and exit are audited. This never grants access to someone else's Gmail.
  • All Data and All Conversations: organisation-wide lists with search and filters. Every view is audited.
  • Organization: users, workspaces, emails, replies, failure rate, campaign performance, approvals and user activity over 7, 30 or 90 days.
  • Audit Logs: who did what, when.
  • System Settings: retention policy (configuration and impact preview only; nothing is deleted automatically), AI provider status, limits and usage, sign-in restriction.

06Before you send

Tick these off for every campaign. Ticks are saved in this browser.

07Limits to know

Only four things send email: Send now on an approved campaign, Send without approval by an admin, a reply you click Send on, and an enabled automation. Nothing else does.
  • Gmail limits. Google caps sends per account per day: typically 500 for an @gmail.com address and 2,000 for Workspace. MailFlow paces at 20 per minute; failures appear in History with the reason.
  • AI. Gemini, 100 requests per person per day and 1,000 per organisation. On the free tier the provider sometimes rate-limits; the panel then says you can continue manually, and nothing else is affected.
  • Replies are pulled, not pushed, for now: use Sync now. Attachments are listed but cannot be downloaded from MailFlow yet.
  • Grid. Datasets over 5,000 rows are filtered over the first 5,000, and the page says so.
  • Approval emails need a connected Gmail on the requester for the request, and on the reviewer or the requester for the decision.
  • Sign-in is open to any Google account today. Ask the super admin to restrict it to @masaischool.com once everyone is onboarded.
